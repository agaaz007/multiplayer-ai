# Controller native lifecycle

`native-lifecycle.mjs` supplies provision/stage/capture/periodic/export operations for Ledger, GBrain, Graphify and the official Supermemory Codex template. These operations do not manufacture derived memories. A successful provisioning receipt is not a readiness pass.

The controller config has `arm`, `root` (existing private sequence directory), `runtime` (frozen compiled runtime), `guide_file`, `version`, and `execution_authorized:true`. Ledger additionally needs `classifier_subscription_authorized:true`. Other products need their pinned native binary/template, controller credential file paths and a budget gate. The setup fails if a native root is already owned.

Run `node native-lifecycle.mjs provision CONFIG.json` once. Each stage request must have `native_config`, `native_profile`, `arm`, `stage`, `workspace`, `fresh_home`, `controller_output_dir` and `runtime`. All stage roots must be inside the sequence directory. `stage REQUEST.json` writes its native profile. `periodic REQUEST.json` runs actual Ledger helper capture every 30 seconds after subscription authentication exists. `capture REQUEST.json` records the actual final capture; `export CONFIG.json` exports stores without deleting them. The sequence controller should stop the periodic process group before its final capture.

`cleanup CONFIG.json` requires a successful export before removing the owned Ledger database or revoking the sequence Supermemory key. Graphify/GBrain stores and exported evidence are retained. Supermemory post-stage processing polls through the same HTTP gate for the configured `provider_wait_ms` (default 120 seconds); incomplete/failed documents stay visible. Graphify post-stage capture uses official extraction only when the agent's saved sources differ from the last extracted corpus, retaining controller-indexing traces.

Ledger uses the existing owned private Postgres/bare Git setup. The v2 controller enables the actual helper classifier and waits for its result; the older pilot adapter remains unchanged. Extraction invokes the native configured extractor command, pinned to subscription Codex `gpt-5.6-sol`, medium reasoning. Each invocation uses an isolated home containing only the stage's subscription authentication. API-key authentication is rejected. Token/time/exit receipts are retained and copied authentication is removed afterwards. Model failures remain capture failures and proposals remain proposals. Task hooks disable autonomous extraction because classifier execution belongs to the controller; periodic native capture performs the intended classification.

GBrain uses a private PGLite home and its native `serve` MCP; Graphify uses the existing scoped adapter around the official extraction/query/graph/feedback CLI. Supermemory materializes the retained official Codex template unchanged, with synchronous Stop flush as in the earlier verified integration. Hook and MCP network traffic must use controller budget proxy URLs; the scoped provider key remains in `supermemory-private.json`, outside the agent sandbox.

Profiles inherit `budget_gate_module`, `budget_file`, `operation_bounds`, and controller `provider_env` overrides. Native MCP call interception is not sufficient to bound asynchronous hooks or unknown server-side billing. Readiness therefore also requires a real receipt with `arm`, `native_version`, `capture_recall_pass:true` and `isolation_pass:true`; setting a readiness boolean in configuration is ignored. Freeze and verify the receipt, guide, binaries, adapter and proxy together before scoring. Do not launch a full-capability claim until live classifier/capture/recall and all paid paths have been verified.

Retained configuration locations (no key values): `.context/competitor-readiness/supermemory-install/native-route.json`, `.context/competitor-readiness/supermemory-install/codex-home-template`, `.context/competitor-readiness/graphify-openai-native.json`, and `.context/competitor-readiness/gbrain-key-file.json`. Existing source pins describe the earlier run; new runs must explicitly pin and smoke their selected installed versions.

## HTTP boundary and live verification

`native-http-proxy.mjs CONFIG.json` binds a loopback port. Each route has a unique surrogate bearer `token`, `sequence`, `provider`, optional Supermemory `namespace`, and a controller-only credential reference. OpenAI routes use `env_file`/`env_name`; Supermemory uses its owned scoped `key_file`. Real credentials are injected only for fixed official HTTPS origins. Native processes receive surrogate credentials and loopback base URLs. Unsupported endpoints, models, rich/remote ingestion, output without a fixed limit, foreign containers and unknown MCP tools fail before provider contact.

The proxy reserves shared budget before every request, including native hooks, retries and post-stage controller indexing. OpenAI generation permits only nonstreamed single text completions with at most 4,096 output tokens. Embedding text and completion input are bounded by UTF-8 request bytes plus framing allowance; known token usage reconciles the reservation. Supermemory reserves all input bytes plus 1,024 framing units at the highest published ingestion rate, ignoring deduplication; unknown actual billing keeps the reservation. This uses the public rate card, not a claim to have inspected the account invoice.

Pricing checked September 12, 2026: [GPT-4.1 Mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) $0.40 input/$1.60 output per million tokens; [text-embedding-3-large](https://developers.openai.com/api/docs/models/text-embedding-3-large) $0.13 per million; [Supermemory](https://supermemory.ai/pricing/) highest rich ingestion $0.010 per 1,000 SM tokens, search $0.005 per 1,000 queries, operations $0.10 per 1,000 operations. Proxy reads reserve $0.001 each conservatively. The source and proxy config hashes must match a successful actual proxy probe receipt before `paid_paths_gated` becomes true.

`native-probe.mjs CONFIG.json` performs unscored transport/capture checks across fresh native MCP processes. Its Supermemory source uses a clearly synthetic transcript fed to the unchanged official flush hook; this is not a task-agent/harness execution claim. September 12 probes recovered exact canaries using GBrain query, Graphify graph query, and Supermemory native search. Supermemory's automatic recall hook did not inject the exact canary; explicit native MCP search did. Actual task sandbox isolation is separately verified by the stage harness.
